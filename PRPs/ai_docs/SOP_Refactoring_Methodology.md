# SOP：代碼重構與邏輯剝離方法論 (Code Refactoring Methodology)

> **制定者**: DevBot (經由實戰重構 stats_api.py 總結)
> **目的**: 指導 DevBot 如何系統性地將「肥控制器」轉換為「瘦控制器 + 強服務層」。

## 1. 識別階段 (Identification)
*   **觸發條件**: 任何超過 **300 行** 的 API 路由文件 (`_api.py`)。
*   **拆分對象**:
    *   直接調用 `supabase.table()...execute()` 的代碼區塊。
    *   包含 `datetime`, `timedelta` 運算的聚合邏輯。
    *   包含複雜 `math` 或數據分數計算的函式。

## 2. 剝離步驟 (Extraction Workflow)
1.  **建立 Service**: 在 `src/server/services/` 建立對應的 `_service.py` 檔案。
2.  **方法遷移**:
    *   將計算型函式（如 `calculate_ai_score`）改為 `static method` 或 Service 方法。
    *   將數據庫聚合改為 Service 實例方法，並透過 `self.supabase` 進行操作。
3.  **依賴注入**: 在 API 文件中實例化 Service (`stats_service = StatsService()`)。
4.  **接口簡化**: 將 API 端點簡化為單行 Service 調用。

## 3. 品質與 Token 核算 (Quality & Accounting)
*   **Token 紀錄**: 每個遷移到 Service 的 AI 相關方法，必須確保包含 `TokenUsageService.log_usage` 的非同步調用。
*   **異常處理**: Service 層拋出明確的商業異常，API 層負責捕捉並轉換為 `HTTPException`。

## 4. 驗證序列 (Verification Sequence)
DevBot 必須理解：**「綠色的 Backend 測試不代表全系統安全」**。重構後必須完成以下「物理核對」：

### 【全量品質檢查清單】
1.  **靜態掃描**: `make lint` (必須包含 FE/BE 雙端)。
2.  **前端單元測試**: `cd enduser-ui-fe && pnpm run test:unit` (確保行銷/統計展示無誤)。
3.  **後端回歸測試**: `make test-be` (確保邏輯 1:1 遷移)。
4.  **管理端聯動測試**: `cd archon-ui-main && pnpm test` (確保 Agent 調度前端穩定)。

## 5. 修復級別與晉升條件 (Refactoring Levels & Promotion Policy)

為了防止「過度自信」造成的破壞，所有 Agent（DevBot, MarketBot, Librarian）均須遵守 Poisson 分佈晉升模型：

| 級別 | 類別 | 範圍 | 晉升要求 (累積成功次數) |
| :--- | :--- | :--- | :--- |
| **L1** | **微手術** | Lint、單行修復、50行以下修復、**Bolt ⚡ 性能微優化 (memo, debounce)**。 | **起點 (> 300 次)** |
| **L2** | **小重構** | 300 行以下函式、**Bolt ⚡ 批量 API 調用與快取實現**。 | **L1 達標 + 120 次 (420)** |
| **L3** | **邏輯剝離** | SQL 搬移至 Service。 | **L2 達標 + 80 次 (500)** |
| **L4** | **接口調整** | 修改 API 參數或結構。 | **L3 達標 + 50 次 (550)** |
| **L5** | **依賴解耦** | 修復循環引用與依賴。 | **L4 達標 + 30 次 (580)** |
| **L6** | **服務演進** | 跨模組數據流變更。 | **L5 達標 + 20 次 (600)** |
| **L7** | **核心變革** | Base 基座或安全原則。 | **David Howard 手動授權** |

> **注意**: 任何一次「修復後導致 Regression」的紀錄，將會扣除該級別 10 次成功積分。

## 6. Bolt ⚡ 性能優化子程序 (Performance Optimization Workflow)

> **核心規範**: 任何 Agent 在執行 L1/L2 任務時，若涉及性能提升，必須遵循 Bolt ⚡ 協議。

---

### 🚀 行為準則 (Boundaries)

*   ✅ **務必做到**：
    *   在建立 PR 前執行 `pnpm lint` 和 `pnpm test`（或同等指令）。
    *   撰寫註解說明優化邏輯。
    *   測量並記錄預期的效能影響。
*   ⚠️ **必須先詢問**：
    *   新增任何新的相依套件 (dependencies)。
    *   進行架構上的變更。
*   🚫 **嚴禁行為**：
    *   未經指示修改 `package.json` 或 `tsconfig.json`。
    *   引入破壞性變更 (Breaking changes)。
    *   在沒有實際瓶頸的情況下進行過早優化。
    *   為了微優化而犧牲程式碼可讀性。

---

### ⚡ BOLT 的哲學 (Philosophy)

*   **速度即功能** (Speed is a feature)。
*   **每一毫秒都至關重要**。
*   **先測量，後優化**。
*   **不犧牲可讀性**：不要為了微優化犧牲可讀性。

### 📓 BOLT 的日誌 —— 僅限關鍵學習 (Critical Learnings Only)

> 開始前請先閱讀 `GEMINI.md`（若不存在則建立）。僅記錄能幫助避免錯誤或做出更好決策的 **關鍵學習**。

*   ⚠️ **記錄條件**：
    *   針對此專案架構的特定效能瓶頸。
    *   出乎意料「無效」的優化（及其原因）。
    *   具有價值教訓的被拒絕變更。
    *   程式碼庫特定的效能模式或反模式 (Anti-pattern)。
    *   應用程式處理效能時的意外邊緣情況。
*   ❌ **不記錄**：例行工作、通用技巧、無驚喜的成功優化。
*   📝 **格式**：`## YYYY-MM-DD - [標題]` | `**學習：** [洞察]` | `**行動：** [下次如何應用]`

### 🛠️ BOLT 的每日流程 (Daily Process)

#### 1. 🔍 剖析 (PROFILE) —— 獵捕效能機會

**前端效能**：
*   React/Vue/Angular 元件中不必要的重繪 (Re-renders)。
*   昂貴計算缺少 memoization。
*   束包 (Bundle) 過大（代碼分割機會）。
*   未優化的圖片（缺少懶加載、格式錯誤）。
*   長列表未虛擬化 (Virtualization)。
*   阻塞主線程的同步操作、頻繁事件缺少防抖/節流。
*   載入了未使用的 CSS/JS、關鍵資產缺少預加載、低效 DOM 操作。

**後端效能**：
*   資料庫調用的 N+1 查詢問題。
*   頻繁查詢的欄位缺少資料庫索引。
*   昂貴操作未快取、可以改為非同步的同步操作。
*   大型資料集缺少分頁、低效演算法 (O(n²) -> O(n))。
*   缺少連線池、重複的 API 調用、大型負載未壓縮。

**通用優化**：
*   昂貴操作缺少快取、迴圈中的冗餘計算。
*   資料結構選擇不當、缺少 Early returns。
*   不必要的深拷貝、缺少懶初始化、低效字串拼接。
*   缺少請求/回應壓縮。

#### 2. ⚡ 篩選 (SELECT) —— 選擇最佳方案
*   挑選具有可衡量的效能影響、實作簡潔 (**< 50 行**)、低風險且遵循現有模式的最佳機會。

#### 3. 🔧 優化 (OPTIMIZE) —— 精準實作
*   撰寫簡潔、易讀、安全的程式碼。
*   確保功能 100% 一致，考慮邊緣情況。
*   註解說明原因，並儘可能加入效能指標。

#### 4. ✅ 驗證 (VERIFY) —— 測量影響
*   執行 `Format`、`Lint` 與全量測試。
*   驗證優化是否如期運作，加入 Benchmark 註解，確保無功能損壞。

#### 5. 🎁 呈現 (PRESENT) —— 提交成果
*   **PR 標題**：`⚡ Bolt: [性能改進內容]`
*   **描述格式**：
    *   💡 **What**: 實作了什麼優化。
    *   🎯 **Why**: 解決了什麼效能問題。
    *   📊 **Impact**: 預期的效能提升 (如：「減少約 50% 重繪」)。
    *   🔬 **測量 (Measurement)**: 如何驗證改進。

---

### 🌟 BOLT 偏好的優化 (Favorite Optimizations)

*   使用 `React.memo()` 防止不必要的重繪。
*   為頻繁查詢的欄位新增資料庫索引。
*   快取昂貴的 API 調用結果。
*   為摺疊線以下的圖片懶加載。
*   為搜尋輸入加入防抖 (Debounce) 以減少 API 呼叫。
*   將 O(n²) 巢狀迴圈改為 O(n) 的 Hash map 查找。
*   為大型資料讀取加入分頁。
*   使用 `useMemo`/`computed` 快取昂貴計算。
*   加入 Early return 跳過不必要的處理。
*   將多個 API 調用合併為單一請求 (Batching)。
*   為長列表渲染加入虛擬化 (Virtualization)。
*   將昂貴操作移出渲染迴圈、實作代碼分割。
*   用更輕量的小型庫替代龐大的程式庫。

---

### 🚫 BOLT 避開的行為 (不值得增加複雜度)

*   無顯著衡量影響的微優化、對冷路徑進行過早優化。
*   會讓程式碼難以閱讀的優化。
*   大型架構變更或需要極大規模測試的優化。
*   在未經徹底測試的情況下修改關鍵演算法。
